# AI 模块需求定义 v4（定稿版）

> 这份文件是唯一的需求口径。架构见 `ai-module-architecture-v3.md`。
> 每条需求都有编号与**可判定的验收**；末尾列出需要产品决策的 5 个问题，我在里面给了推荐答案。

---

## 0. 一页结论

这个模块的用户只关心四件事，按重要性排：

1. **能不能用**（配好了吗、网络通吗、密钥对吗）
2. **用的是哪个**（平台、模型）
3. **要等多久**（首字多快、整体多慢）
4. **出问题该改哪**（不是"失败了"，而是"哪一步失败了"）

现在的问题不是界面丑，而是**信息没有归属**：测速是列表里的一行、连接状态不存在、地址既在连接区又在高级区、模型能力散在三处。v4 的要求是：**每个事实只有一个位置，每个位置只回答一个问题。**

## 1. 调研证据

### 1.1 说明（必须先讲清）

本环境里 `github.com` 与 `raw.githubusercontent.com` 被 DNS 拦截，无法逐行读源码：

```
URL hostname "github.com" resolves to a non-public IP address
```

因此下面的依据分两档：**A 档＝这次实际抓到的页面原文**；**B 档＝搜索结果摘要 + 该产品既有行为**。凡是 B 档，请按"参考"而不是"确证"看待。

### 1.2 逐项证据与取舍

| # | 项目 | 关键做法 | 档 | 我们采用 |
| --- | --- | --- | --- | --- |

| 2 | 同上 | 社区最强烈的诉求是"**同一供应商配多个 key**"（多个 OpenAI 兼容地址） | A | 采用：平台不是"供应商"，是"一套连接"，允许同模板多个实例 |

| 5 | [gpt_mobile](https://github.com/taewan-p/gpt_mobile#1) | Android + Material3，一个 provider 一份密钥 + 模型多选 | A | 部分采用：单选用勾，多选留给"批量删除" |

| 13 | big-AGI | 模型能力矩阵（上下文/价格/模态） | B | 部分采用：上下文长度入行，能力徽章后续再加 |

### 1.3 从调研里得到的四条硬结论

1. **provider 与 model 必须分家**（LobeHub）。我们现在把"测速"这个对模型的动作塞在模型列表里当一行，正是没分家的表现。
2. **健康检查结果要内联**（Cherry Studio）。toast 是"发生过"，行内是"现在是什么"。
3. **"通不通"和"多快"是两个问题**（Open WebUI）。前者是连接状态，后者是模型性能，不能共用一套文案。
4. **延迟数据要可比较**（OpenRouter / LM Studio）。单个数字无意义，要么给基线，要么给分级。

## 2. 信息架构（定稿）

### 2.1 页面清单

| 页面 | 存在的理由 | 一屏要回答的问题 |
| --- | --- | --- |
| 对话页 | 主场景 | 我问了什么、它答了什么 |
| 历史面板 | 找回 | 之前问过什么 |
| 设置页 | 现状 + 入口 | 我现在用哪个平台哪个模型 |
| 平台列表 | 管理多个连接 | 我有几套可用配置 |
| 平台详情 | 配置一套连接 | 这套配置通不通、模型有哪些、哪个快 |
| 通话页 | 免手操作 | 它在听吗、它听到了吗、它说的什么 |

### 2.2 平台详情页区块（定稿）

顺序固定，每块只回答一个问题：

```
① 身份      平台名（页标题）+ 模板徽章 + 当前模型           "这是哪套配置"
② 连接      测试连接（含结果） + API Key                     "它通不通"
③ 模型      模型 · N 个    [全部测速]                        "有哪些、哪个快"
             每行：勾 · 名称 · 首字·总·上下文 · ⋯
             ＋ 添加模型
④ 高级(折叠) 接口地址 / 协议                              "改坏了怎么办"
⑤ 危险区    删除平台（卡外、左对齐）                          ——
```

规则：
- ① 由页面标题承担，不再单独做一张卡（上一版用首字母方块，属于装饰）。
- ② 的测试结果**永远显示在行上**，不出现 toast。
- ③ 的测速是区块动作，不是列表行；单条重测在行尾 ⋯。
- ④ 默认收起；展开后也不影响 ②③ 的位置。

## 3. 需求清单

### R-01 平台（一套连接）

- 定义：平台 = 一套可独立使用的连接配置（模板 + 地址 + 密钥 + 协议 + 模型集合）。
- 允许同一模板创建多个实例（两个 OpenAI 兼容地址各一份），名称可区分。
- **验收**
  - 内置模板创建后地址预填并标注"官方地址"；
  - 自定义平台允许私有地址 http，公网 http 被拒并说明原因；
  - 删除需二次确认；删除当前平台后设置页回到"还没有接入平台"；
  - 同一模板可创建第二个实例，名称可改，互不影响。

### R-02 连接状态

- 组成：`测试连接` 一行，右侧是该套配置最近一次的连通结果。
- 值域：`测试` （从未测） / `测试中…` / `连接正常 · 首字 1.0 s` / `连接失败` / `连接超时`。
- 语义：测试 = 用当前选中的模型发一次最小请求，等价于 Open WebUI 的第 ③ 级"深度健康检查"。
  - 它同时证明四件事：网络通、地址对、密钥对、该模型能出字。
  - **不新造 ping 链路**：多一条链路就多一处会和真实调用不一致的地方。
  - 文案要说清它证明的范围（`连接正常 · 首字 1.0 s`），不要写成 `网络正常`——那会让人以为只测了网。
- **验收**
  - 结果随时可见，重进页面仍在（随配置持久化）；
  - 点击后 1 秒内行内出现"测试中…"，结束换结果；
  - 密钥为空时该行不可点，并写明"先填 API Key"。

### R-03 模型列表

- **来源只有两种**：平台 `GET /models` 拉回来的真实模型，或用户手填的模型 id（自定义模型）。
  APP 不预置任何厂商默认模型，也不在拉取后自动选中；平台没返回的模型不应出现在列表里。
- 组成：`模型 · N 个` 标题 + `全部测速` 动作 + 行 + `添加模型`。
- 每行：选中勾 · 模型名 · 事实行 · ⋯。
- 事实行（` · ` 连接，最多三段）：首字与总时长 → 上下文长度 → （手动添加且无其它事实时）"手动添加"。
- 数量 > 8 时，标题行下方出现搜索框，按名称/id 过滤。
- **验收**
  - 0 个模型：列表内一行"还没有模型 / 拉取列表或手动填一个 id"，点击开菜单；
  - 选中哪个，对话页立刻用哪个；
  - `添加模型` 打开菜单：拉取模型 / 手动添加；
  - 手填的模型与当前模式对不上时（文本模式填了实时模型、语音模式填了对话模型）给出提示；
  - `⋯` 含：测这一条 / 设为当前 / 删除模型。

### R-04 速度，分两处、两个含义

这是两件不同的事，不许再混成一个"测速"：

#### R-04a 对话页：真实对话采样（不额外发请求）

- 数据来源：用户每一次真实回答的 usage 与时间戳，**不额外发探测请求**。
- 展示两档：
  - **实时速度**：流式输出过程中显示 `38 tok/s`（按已收到的 token / 已用时滚动更新），停止后冻结为最终值。
  - **每轮平均**：每条回答末尾元信息行显示 `首字 0.8 s · 41 tok/s`；会话头部（或历史行）显示本次会话的平均 `平均 39 tok/s`。
- 没有 usage 的数据（平台不回报）只显示首字，不显示 tok/s，也不显示 0。
- 验收：
  - 流式过程中数字会变，停止后不再变；
  - 平台不回报 usage 时，该位置只出现首字；
  - 同一会话内多次回答的平均值按 token 加权，不是简单算术平均。

#### R-04b 平台详情页：探针首字（对应其他项目的 URL 连通测速）

- 语义：对每个模型发一次最小请求，**只测"多久开始出字"**，不测吞吐——探针的回答只有一段，没有生成窗口，算吞吐没有意义（本轮已在真机证实：首字与总时长几乎相等）。
- 展示：模型行 `首字 645 ms · 1M 上下文`；慢的判定用同平台内相对比较。
- 状态机：`未测 → 测速中 →（成功 | 失败 | 超时）`；正在测的行显示"测速中…"；不弹完成 toast。
- 验收：见上一版（行内结果、可取消、结果持久化）。

### R-05 高级

- 内容：接口地址、协议。
- 默认收起，收起时显示一行摘要：协议名 + 地址。
- **验收**：收起态不占超过一行；展开后四个字段与连接区左缘对齐；修改即时保存。

### R-06 对话

- 组成：页头（历史 · 标题 · 通话 · 更多）· 消息流 · 输入条。
- 助手回答：通栏正文，不套卡；末尾一行元信息（模型 · 耗时 · tokens）。
- **验收**
  - 流式中发送键变停止；停止后已输出保留；
  - 失败给原因 + 重试（只重发这一条）；
  - 未接平台 / 无模型 / 无网络三种文案互不混淆；
  - 有模型时输入条上方不重复显示模型名（回答上方已有）。

### R-07 语音通话

- **验收**
  - 动效只在聆听/思考/说话时出现；静音、失败、结束静止；
  - 单一主按钮：可修配置时"去设置"，临时故障时"重试"；
  - 失败说明缺哪一步（没选实时模型/平台缺 Key/鉴权/网络）。

### R-08 历史

- 四态：加载 / 空 / 内容 / 读取失败。
- **验收**
  - 标题一行（≤16 码点）、摘要一行（≤12 码点），时刻在标题行右端（当前实现已满足）；
  - 读取失败显示"没能读取对话记录 + 重试"；
  - `清空全部` 在列表卡之外、左对齐、二次确认。

### R-09 用量（已下线）

> 2026-10-29：设置页不再展示请求次数 / 令牌 / 费用，也不再写 `usage/requests.jsonl` 账本。
> 记录、聚合、读取三层代码（`RecordUsage`、`AiUsageSummary`、`FileAiUsageStore`、`LoadUsageSummary`）全部删除。
> 单条消息的 token 元信息仍显示在对话气泡上，来源是平台响应的 `usage`，不经过账本。

### R-11 生成参数：不再暴露给用户

> 2026-10-29 调整：原「全局参数 + 模型参数」两级方案整体下线。设置页与平台详情页不再出现任何参数控件。

- 温度、top_p、最大输出、上下文条数一律由 APP 在发请求时给定默认值，定义在
  `domain/ai/model/AiGenerationDefaults`：温度 0.7、top_p 1.0、最大输出 4096、上下文 20 条。
- 采样参数在 `LibAiChatGateway.toRequest()` 填入（APP 调用 lib_ai 的位置）；上下文条数在
  `AiChatSession.beginRun()` 使用。
- 用户唯一可改的生成相关设置是**系统提示词**。
- **理由**：这些是产品参数而非用户偏好。摆出滑杆会让人以为必须调，实际几乎没人动；
  而"留空让平台决定"又会让同一句话在不同模型上风格不一致，出问题无法归因。
- **验收**
  - 设置页「回答风格」只有一行系统提示词；
  - 平台详情页高级区只有名称 / 接口地址 / 协议；
  - 模型菜单只有「测这一条」与删除；
  - 每次请求都带上同一套采样参数，与模型、平台无关。

### R-10 设置页

- 组成：页面最上方的接入形态分段（文本模式 / 语音交流模式）· 身份卡（平台 + 模型 + 更换）· 当前模式的分区。
  - 文本模式：回答风格（系统提示词）。
  - 语音交流模式：语音链路（实时语音 · 一条连接直连）。
- 两种模式各自保存选中的平台与模型，切换分段不覆盖对方的选择。
- **验收**：
  - 分段两段永远可点，切换即时持久化；
  - 身份卡显示当前模式对应的模型（文本 → 对话模型，语音 → 实时模型），空态说缺哪一类；
  - 提示词一行预览，点开弹窗编辑；
  - 语音模式不再出现转写模型、音色、静音阈值——APP 侧已移除 ASR → LLM → TTS。

## 5. 术语表（界面文案统一）

| 概念 | 用词 | 不用 |
| --- | --- | --- |
| 一套连接 | 平台 | 供应商、通道、接口 |
| 第一个字到达的耗时 | 首字 | 延迟、ping、响应时间 |
| 生成速率 | tok/s（实时速度 / 平均速度） | 吞吐、速度值、tokens per second 全称 |
| 完整一轮耗时 | 总（仅在没有 usage 时作为退路） | 总耗时、全量时间 |
| 连通性检查 | 测试连接 | 测速、检测 |
| 性能测量 | 测速 / 全部测速 | 检测、ping |
| 上下文长度 | 128K 上下文 | 上下文窗口、token 上限 |

## 6. 非功能

- 冷启动到 AI 页可交互 ≤ 800 ms。
- 所有磁盘与网络操作不占主线程。
- 同一时刻最多一个测速任务。
- 单测覆盖 mapper / policy / usecase / ViewModel 状态迁移；页面靠真机截图。
