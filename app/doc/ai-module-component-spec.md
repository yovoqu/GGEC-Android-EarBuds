# AI 模块组件规格（全量重构依据）

> 逐组件回答四件事：**职责**、**为什么要有**、**别的产品怎么做**、**我们的决定**。
> 依据分档：**A＝本次抓到原文**，**B＝搜索结果/已知行为**。凡是没查到的，写"未查证"，不编。
> 需求口径见 `ai-module-requirements.md`；分工见 `ai-module-architecture-v3.md`。

## 0. 页面与组件的从属关系

```
对话页 ChatPage
├ 页头 Header（历史 / 标题 / 通话 / 更多）
├ 消息流 MessageList
│  ├ 空态 EmptyState
│  ├ 用户消息 UserMessage
│  ├ 助手消息 AssistantMessage
│  │  ├ 思考过程 ReasoningBlock
│  │  ├ 正文 MarkdownView
│  │  └ 元信息 MetaLine（首字 · tok/s · tokens）
│  └ 消息操作 MessageActions（复制 / 重发 / 删除）
├ 流式指示 StreamingIndicator（打字点 + 实时速度）
└ 输入条 Composer（输入框 / 发送·停止 / 状态）

历史面板 HistorySheet
├ 面板头（页名 / 新建）
├ 列表行 HistoryRow（勾 / 标题 / 摘要 / 时刻 / ⋯）
├ 清空行（卡外）
└ 四态：加载 / 空 / 内容 / 读取失败

设置页 SettingsPage
├ 身份行 IdentityRow（平台 / 模型 / 更换）
├ 说话方式 ModeSegmented
├ 参数区 ParamsSection（全局开关 + 作用范围 + 滑杆）
├ 回答风格 PromptRow
└ 用量 UsageBlock

平台详情 PlatformPage
├ 连接区 ConnectionSection（测试连接 / API Key）
├ 模型区 ModelsSection（标题+全部测速 / 行 / 添加模型）
├ 高级区 AdvancedSection（地址 / 协议 / 参数来源）
└ 危险区 DangerZone（删除平台）

通话页 CallPage
├ 页头（关闭 / 标题 / 模式）
├ 光晕 Orb
├ 状态行 StatusLine
├ 失败出口 Actions（去设置 / 重试）
└ 控制排 Controls（拍照 / 麦克风 / 扬声器 / 挂断）
```

## 1. 对话页

### 1.1 页头 Header

- **职责**：标识当前上下文（这是 AI 页），并给出三个去处：历史、通话、更多。
- **为什么**：对话页没有导航栏空间，历史与设置必须从别处进；通话是主场景之一，必须一屏可达。
- **别家**：ChatGPT 把模型选择放左上、新对话在右上；gpt_mobile 用抽屉放全部次要入口（**B**）。
- **我们的决定**：左＝历史图标（带当前会话无关的通用形态）；中＝「AI」20sp；右＝通话（品牌色，主入口）+ 更多「⋯」（新对话 / 设置）。
  - 不做抽屉：手机上一屏只有一次滑动预算，留给消息流。
  - 模型名不放页头：它会变，放进消息元信息更准。
- **验收**：页头高度 56dp；点击区 ≥40dp；「⋯」菜单两项且互不遮挡。

### 1.2 消息流 MessageList

- **职责**：按时间顺序承载消息，并在新消息到来时保持"最后一条可见"。
- **为什么**：这是页面主体；滚动行为决定"读起来顺不顺"。
- **别家**：ChatGPT 流式时自动贴底，用户上滑后停止自动滚动（**B**）；LobeChat 有"回到底部"浮钮（**B**）。
- **我们的决定**：默认贴底；用户上滑后不再抢滚动；不引入浮钮（一屏内容通常 < 2 屏）。
- **验收**：流式中上滑不被拉回；停止输出后不回弹。

### 1.3 空态 EmptyState

- **职责**：在没有消息时，用一句话说明"这里能干什么"。
- **为什么**：新装用户第一次进入，全是空白会以为坏了。
- **别家**：ChatGPT 给示例问题卡片；Cherry Studio 给能力分类入口（**B**）。我们上一版也抄过示例问题，被判定为"编内容"。
- **我们的决定**：一句真话「耳机有什么问题？」；有实时语音模型时加一行「直接问，或者点右上角通话说给它听」。**不做示例问题**——那是我们编的，不是产品事实。
- **验收**：空态只有标题（+ 条件性一行副标题）；无插画、无渐变。

### 1.4 用户消息 UserMessage

- **职责**：区分"我说的"与"它说的"。
- **为什么**：这是对话最基本的可读性。
- **别家**：ChatGPT 用右侧浅灰气泡；Claude 用整段带底色（**B**）。
- **我们的决定**：右对齐浅灰气泡，圆角 `18,18,6,18`（右下角小一号暗示"从右边说出来"），文字 15sp 主文色。
- **验收**：长文本自动换行且最大宽度不超过屏宽 82%；不做全屏宽度。

### 1.5 助手消息 AssistantMessage

- **职责**：承载回答正文与它的来源信息。
- **为什么**：答案是一屏里唯一要读的东西。
- **别家**：多数产品（ChatGPT / LobeChat / NextChat）助手回复不套卡片（**B**）；少数（早期 Chatbox）用卡片。
- **我们的决定**：通栏正文，无卡片、无气泡；上方一行 12sp 灰字标模型名；末尾一行元信息。
- **验收**：正文左右边距 20dp；连续段落之间有段距；不出现卡片阴影。

### 1.6 思考过程 ReasoningBlock

- **职责**：让愿意看的人看到推理，同时不干扰只想看结论的人。
- **为什么**：推理模型（DeepSeek-R1 类）会返回 reasoning，默认展开会把答案挤到屏幕外。
- **别家**：ChatGPT 折叠为一行「Thought for 12s」（**B**）；Claude 用可展开区块（**B**）。
- **我们的决定**：默认收起，一行「思考过程 · 12s」+ 展开箭头；展开后是灰色小字块，与正文有明显层级差；**流式时若还在思考，这一行显示"正在思考…"而不是没有反馈**。
- **验收**：收起态高度 = 一行；展开态不改变正文位置之外的布局。

### 1.7 元信息 MetaLine

- **职责**：回答"用了哪个模型、花了多久、多少 token"。
- **为什么**：用户排障与成本感知都需要；这是我们与"单纯聊天壳"的区别。
- **别家**：OpenRouter 每次生成都有可查的 logs（延迟/吞吐/token，**A**）；LM Studio 响应里带 `time_to_first_token`、`tokens_per_second`（**A**）；多数移动客户端不显示。
- **我们的决定**：`首字 0.8 s · 41 tok/s · 168 tokens`；平台不回报 usage 时只显示首字，**不显示 0 或估算值**。
- **验收**：三段顺序固定；无数据时对应段消失而不是显示占位。

### 1.8 消息操作 MessageActions

- **职责**：对单条消息做三件事：复制、重发、删除。
- **为什么**：复制是最高频（把答案发给别人）；重发用于回答不满意。
- **别家**：ChatGPT 悬停出图标（桌面）/长按出菜单（移动，**B**）。
- **我们的决定**：助手消息下方常显三个图标（复制/重发/删除），用户消息长按出菜单（复制/删除）。常显是因为移动端没有悬停，藏起来等于没有。
- **验收**：图标点击区 ≥40dp；删除需二次确认；重发只在最后一条助手消息上可用。

### 1.9 流式指示 StreamingIndicator

- **职责**：回答还没开始出字时，说明"它在工作"。
- **为什么**：首字可能要 1–3 秒，无反馈会被当成没反应。
- **别家**：三点动画（多数）；ChatGPT 显示闪烁光标（**B**）。
- **我们的决定**：三点动画 + **实时速度**（`38 tok/s`，随 token 到达滚动更新）；开始出字后三点消失，速度保留在元信息里。
- **验收**：速度在流式中变化、结束后冻结；不显示"思考中"与"三点"两套指示。

### 1.10 输入条 Composer

- **职责**：输入、发送、停止。
- **为什么**：唯一的输入通道。
- **别家**：ChatGPT 单行变多行、右侧发送变停止（**B**）。
- **我们的决定**：单行胶囊输入框；右侧按钮三态：空＝浅灰箭头（明显不可用）、有字＝品牌蓝箭头、生成中＝停止方块。**模型名不在这里重复显示**；没有模型时这一行才出现，写明原因。
- **验收**：三态切换即时；键盘弹出时输入条随之上移且不被遮挡。

## 2. 历史面板

### 2.1 面板头 PanelHeader

- **职责**：说明这是什么面板，并提供"新建对话"。
- **为什么**：面板是独立窗口，没有它就没有标题。
- **别家**：ChatGPT 侧栏顶部有搜索（**B**）。
- **我们的决定**：页名「历史记录」20sp + 右侧新建图标；**不做搜索**（会话量通常 < 50）。

### 2.2 列表行 HistoryRow

- **职责**：一行说清"这是哪次对话、什么时候"。
- **为什么**：用户靠标题与时刻认领会话。
- **别家**：ChatGPT 行内只有标题；Cherry Studio 有摘要与时间（**B**）。
- **我们的决定**：勾（当前会话）+ 标题（≤16 码点，一行）+ 摘要（≤12 码点，一行）+ 时刻 + ⋯。标题与摘要各占一行，时刻挂在标题行右端。
  - 长度是算出来的：15sp 中文在本机行宽下，扣掉图标与时刻只剩约 14 字，超过就折行，折行会让时刻落到第二行中间（上一版实测过）。
- **验收**：任意长度标题都不折行；时刻与 ⋯ 垂直居中于标题行。

### 2.3 清空行 ClearRow

- **职责**：一次删除全部会话。
- **为什么**：隐私与"重新开始"的需求真实存在。
- **别家**：多在设置里（**B**）。
- **我们的决定**：在列表卡之外、面板底部、左对齐 20dp、破坏色、二次确认。**不放进列表**——放进去就变成"第二行会话"，误触代价是唯一记录。

## 3. 设置页

### 3.1 身份行 IdentityRow

- **职责**：回答"我现在用哪个平台的哪个模型"。
- **为什么**：这是设置页存在的首要理由。
- **别家**：LobeHub 把 provider 与 model 分成两个独立配置区（**A**）。
- **我们的决定**：一行显示平台名（20sp）+ 当前模型（13sp 灰）+「更换」；点击「更换」弹出平台列表。不做首字母头像（上一版做过，是装饰）。

### 3.2 说话方式 ModeSegmented

- **职责**：在"识别→回答→朗读"与"全双工实时"之间选。
- **为什么**：两条链路的成本与体验不同，用户要能选。
- **别家**：多以开关或下拉呈现（**B**）。
- **我们的决定**：两段分段控件；不可用的段压暗并在下方写一行原因（如「先在平台里添加一个实时语音模型」）。**不用禁用状态糊过去**。

### 3.3 参数区 ParamsSection（R-11）

- **职责**：控制生成参数，两级：全局默认 + 模型级覆盖。
- **为什么**：不同模型对温度敏感度不同；但多数用户只想设一次。
- **别家**：SillyTavern 分"连接/生成/界面"三组，生成参数较深（**B**）；Open WebUI 参数在模型配置里（**A** 文档层面）。
- **我们的决定**：全局开关默认关闭；打开后选作用范围（仅某个模型 / 当前平台全部 / 全部模型）；滑杆未设置时不画拇指、右侧写「平台默认」；模型被单独设置后固定，不再被全局覆盖。
- **验收**：三种来源（此模型 / 全局 / 平台默认）在界面上可区分。

### 3.4 用量 UsageBlock

- **职责**：请求次数、令牌、费用。
- **为什么**：自配平台是用户自己的钱。
- **我们的决定**：三行 k-v；平台未上报费用时显示「未上报」而不是 0.00。

## 4. 平台详情页

### 4.1 连接区 ConnectionSection

- **职责**：回答"这套配置通不通"。
- **为什么**：配错是本模块最常见的失败原因。
- **别家**：Open WebUI 把健康检查分三级：服务在不在 / 提供商连不连得上 / 真实推理通不通（**A**，原文：「Open WebUI 可能运行正常，而您的模型提供商却挂了」）。Chatbox 把测试做成独立一步、结果留页面（**B**）。
- **我们的决定**：两行——`测试连接`（右侧是最近结果）+ `API Key`（带显示切换）。测试＝第 3 级：真发一次最小请求，因此文案写「连接正常 · 首字 1.0 s」而不是「网络正常」。
- **验收**：结果随配置持久化；密钥为空时不可点并写明原因；不弹 toast。

### 4.2 模型区 ModelsSection

- **职责**：回答"有哪些模型、哪个能用、哪个快"。
- **为什么**：模型选择直接决定回答质量与成本。
- **别家**：Cherry Studio 把健康检查结果**内联进列表**（**B**，其重构文章标题即"迁移到列表内联"）；LM Studio 模型对象自带 `max_context_length`、`state`（**A**）；LobeHub 模型按类型分组并支持排序（**A**）。
- **我们的决定**：
  - 标题行 `模型 · N 个` + 动作 `全部测速`（测速是区块动作，不是列表行）。
  - 行：勾 · 名称 · 事实行（`首字 645 ms · 1M 上下文`，最多三段） · ⋯（测这一条 / 设为当前 / 删除）。
  - `添加模型` 一步分两条路（拉取 / 手动）。
  - 数量 > 8 时出现搜索框。
- **验收**：见 R-03。

### 4.3 高级区 AdvancedSection

- **职责**：放不常改但错了就整页不工作的三项：接口地址、协议、参数来源。
- **为什么**：默认展开会挤掉模型列表；全部藏起来又会让排障无路可走。
- **别家**：SillyTavern 高级项折叠（**B**）。
- **我们的决定**：默认收起，收起态一行摘要（协议名 + 地址）；展开后三项 + 参数来源标注（`温度 0.7（此模型 / 全局 / 平台默认）`）。

### 4.4 危险区 DangerZone

- **职责**：删除平台。
- **为什么**：破坏性动作必须有出口，但不能抢注意力。
- **我们的决定**：卡片之外、左对齐 20dp、破坏色、二次确认、与上方卡片间隔 32dp。

## 5. 通话页

### 5.1 光晕 Orb

- **职责**：把"声音在流动"变成可看的。
- **为什么**：语音没有画面反馈，用户不知道对方听没听到。
- **别家**：ChatGPT 语音用呼吸球，静音时停止动画（**B**）。
- **我们的决定**：只在聆听/思考/说话三态呼吸；聆听时半径跟真实电平；静音、失败、结束静止；失败态中性灰、无光晕。**没有假动效**——对话页不做波形，就是因为它没在听。

### 5.2 状态行 StatusLine

- **职责**：一句话说明当前处于哪一步。
- **别家**：多为一句短文案 + 模式副标题（**B**）。
- **我们的决定**：单行；失败时两行（结论 + 原因），原因降一档字号与颜色。

### 5.3 失败出口 Actions

- **职责**：给一条能走出去的路。
- **为什么**：语音失败最常见是配置问题，没有出口就是死胡同。
- **我们的决定**：只有一个主按钮——能靠改配置解决的（找不到接口/鉴权/无模型）→「去设置」；只可能是临时故障的（网络/超时/服务端/限流）→「重试」。另一个隐藏，因为点了也没用。

### 5.4 控制排 Controls

- **职责**：拍照占位、静音、扬声器、挂断。
- **我们的决定**：四个 56dp 圆钮；结束/失败后三钮置灰、挂断降级为中性；**没有文字标签**（图标语义足够，加标签会挤）。

## 6. 全局约束（对每个组件都成立）

1. 一屏一个主角；除主角外不加阴影、不加第二层卡片。
2. 品牌色只给主操作与进行中；选中用勾形 + 字重。
3. 字号只用 20 / 15 / 13 / 12；页边距 20dp；行高 56dp 网格。
4. 不用 toast 承载状态，只用于"操作已生效"类确认。
5. 每个组件的加载 / 空 / 内容 / 错误 / 离线 / 无权限 / 禁用，缺一不可（矩阵见需求文档 §4）。
